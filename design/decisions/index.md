# Concepts

* [0001-build-bespoke-rust-tool](0001-build-bespoke-rust-tool.md) - Build our own filtering/mapping engine; use josh as a design reference, not a dependency.
* [0002-hybrid-git-backend](0002-hybrid-git-backend.md) - git2-rs for local object/merge work; real git subprocess for push/fetch.
* [0003-mapping-state-in-commit-trailers](0003-mapping-state-in-commit-trailers.md) - Source<->dest mapping lives in commit-message trailers; decision 0025 requires an authenticated final state block before a trailer can drive resume or loop-prevention.
* [0004-exclude-list-versioned-in-source](0004-exclude-list-versioned-in-source.md) - Exclude-list is a committed, gitignore-style file inside source, not external config.
* [0005-branch-pairs-are-a-configured-list](0005-branch-pairs-are-a-configured-list.md) - N branch-pairs cost the same as 1; config is a list from day one.
* [0006-setup-uses-real-shared-history](0006-setup-uses-real-shared-history.md) - source's first commit is a real child of dest's tip; every future merge gets a native git merge-base.
* [0007-conflict-policy-hard-stop](0007-conflict-policy-hard-stop.md) - A real dest<->source conflict hard-stops that pair's sync rather than auto-resolving or skipping.
* [0008-ship-resolve-helper](0008-ship-resolve-helper.md) - `gitprism resolve` reproduces the conflict, hands off to normal git UX, and closes the trailer bookkeeping loop.
* [0009-push-race-refetch-and-recompute](0009-push-race-refetch-and-recompute.md) - A lost ff-only push race is handled by refetching dest and recomputing, not rebasing.
* [0010-preserve-author-stamp-committer](0010-preserve-author-stamp-committer.md) - Original author is preserved; gitprism stamps itself as committer, matching git's own rewrite conventions.
* [0011-exclude-list-is-gitignore-syntax](0011-exclude-list-is-gitignore-syntax.md) - Exclude-list is `.gitprismignore` using exact `.gitignore` syntax, self-excluding by default.
* [0012-config-versioned-in-source](0012-config-versioned-in-source.md) - Config (repo locations, branch pairs, committer identity) is `.gitprism.toml`, versioned in source, self-excluding like `.gitprismignore`; `setup` bootstraps it from disk before source's first commit exists.
* [0013-repo-urls-optional-fall-back-to-env-vars](0013-repo-urls-optional-fall-back-to-env-vars.md) - `[source].url`/`[dest].url` are optional in `.gitprism.toml`, falling back to `GITPRISM_SOURCE_URL`/`GITPRISM_DEST_URL` when omitted — keeps per-environment remotes out of source's committed history; the env vars are not a credential-secrecy mechanism (2026-08-21 addendum).
* [0014-source-to-dest-becomes-diff-based-and-can-conflict](0014-source-to-dest-becomes-diff-based-and-can-conflict.md) - source→dest applies each pending commit as its own filtered diff, not a full-tree snapshot — required once dest→source can land content between two not-yet-pushed source commits; supersedes decisions/0009's "no merge semantics," extending decisions/0007's hard-stop to source→dest too.
* [0016-both-directions-merge-via-real-git-merge-tree](0016-both-directions-merge-via-real-git-merge-tree.md) - Both sync directions delegate the 3-way merge to a real `git merge-tree --write-tree` subprocess over pre-filtered trees, replacing source→dest's non-idempotent patch application *and* dest→source's `cherrypick_commit`; supersedes decisions/0014's mechanism and amends decisions/0002's local-merge clause.
* [0015-resolve-real-git-cherry-pick-explicit-continue](0015-resolve-real-git-cherry-pick-explicit-continue.md) - `gitprism resolve <pair>` drives a real `git cherry-pick` subprocess (so conflicts get ordinary working-tree markers), identifies the commit by recomputing sync's own pending list, and resumes only via an explicit `--continue` flag matching git's own convention. Dest→source only for now; source→dest's diff-conflict shape is a follow-up.
* [0017-source-to-dest-mirrors-every-branch](0017-source-to-dest-mirrors-every-branch.md) - source→dest discovers and mirrors every branch on source under its own name, no config entry needed; dest→source keeps an explicit configured list, simplified to plain branch names now that source→dest never renames. Supersedes decisions/0005's shared-pairs-list model for source→dest's scope. Branch deletion is explicitly out of scope: gitprism never deletes a branch on either side.
* [0018-branch-deletion-failure-modes](0018-branch-deletion-failure-modes.md) - Resolves the two branch-deletion edge cases decisions/0017 deferred: a round-tripped branch's dest ref going missing is a hard-fail with a clear message (source and dest are out of sync); a mirror-only branch's dest ref going missing is checked, content-first via `git merge-tree` and with no persisted state, against whether it's already fully merged into a round-tripped branch's current tip before deciding whether to recreate it — following GitLab push-mirror's and git-trim's documented precedent for exactly this distinction.
* [0019-marker-scans-are-first-parent-only](0019-marker-scans-are-first-parent-only.md) - Resolves design/log.md's long-standing "trailers are not pair-qualified" gap: `newest_source_marker`/`newest_dest_marker` now revwalk first-parent-only (`Revwalk::simplify_first_parent()`), git's own canonical mechanism for excluding a merged-in branch's own history, so a real two-parent merge of a mirror-only branch into a round-tripped branch can no longer hand the round-tripped branch's resume scan the merged-in branch's own marker. Documented limitation: assumes the tracked branch is first-parent of its own merges.
* [0020-sync-status-output-is-a-pinned-progress-display](0020-sync-status-output-is-a-pinned-progress-display.md) - `sync`'s five plain `eprintln!` call sites become an `indicatif`-backed display, Gradle rich-console-style: a pinned overall progress bar (total computed upfront, not discovered mid-run) with the current branch/step below it, and every completed branch-operation printed as a colored, scannable summary line above (done/skipped/error in green/yellow/red, round-tripped branch names in cyan vs. plain for mirror-only, explanatory text demoted to a note line) — falling back to today's plain lines whenever stderr isn't a terminal.
* [0021-setup-accepts-a-clean-clone-of-dest](0021-setup-accepts-a-clean-clone-of-dest.md) - `setup`'s "repo must be completely empty" precondition relaxes to "every existing local branch's tip is identical to dest's own current tip for that name, and no other local branches exist" — recognizing `git clone <dest-url> && cd && gitprism setup` as a safe starting state rather than rejecting it outright, while still hard-failing on any real independent history (including a previous `setup` run's own graft commits). Amends decisions/0012's "completely empty repo" consequence.
* [0022-setup-gains-an-interactive-first-run-wizard](0022-setup-gains-an-interactive-first-run-wizard.md) - When `setup`'s resolved config path is missing and stdin/stdout is a terminal, `setup` interactively prompts for dest's URL (prefilled from an existing `origin` remote), branches (discovered via `git ls-remote`, sorted with long-lived names first, plus manual free-text), source's URL (skippable, per decisions/0013), and committer identity (prefilled from local git config), offers to repoint/add `origin` to source's URL once known, writes `.gitprism.toml` from the answers, then runs `setup`'s existing logic unchanged. A missing config with no attached terminal still hard-fails exactly as before.
* [0023-setup-reconciles-pre-existing-branches-via-merge-base](0023-setup-reconciles-pre-existing-branches-via-merge-base.md) - Generalizes decisions/0021's oid-equality precondition into a real merge: a pre-existing local branch is reconciled with dest via git's own merge-base plus decisions/0016's `merge_tree` primitive, producing a two-parent commit (local tip first, dest tip second) when real shared history exists, hard-stopping on any real content conflict per decisions/0007. A branch with no merge-base at all — genuinely unrelated history — hard-fails unconditionally, with no flag or override to force it through gitprism itself; combining truly unrelated histories is left to real git, done deliberately before setup runs. A branch already carrying a `Gitprism-Dest-Commit` trailer (setup's own prior output) hard-fails too, before the merge-base question even arises — preserving decisions/0021's "setup never re-runs against itself" guarantee that the merge-base generalization would otherwise have silently broken. Supersedes the `--adopt`-flag mechanism this decision originally proposed. Local branches outside `config.branches` remain untouched, as already decided.
* [0024-sync-warns-and-continues-past-a-mirror-only-branch-with-no-shared-history](0024-sync-warns-and-continues-past-a-mirror-only-branch-with-no-shared-history.md) - Resolves the assumption decisions/0017 flagged as unverified: a discovered local branch with no ref on dest yet and no `Gitprism-Dest-Commit` trailer anywhere in its first-parent history (real independent history predating `gitprism setup`, or an untouched stray branch per decisions/0021) is reported via a new `Outcome::Warning` (magenta, extending decisions/0020's palette, distinct from `Outcome::Skipped`'s yellow and genuinely benign meaning) and `sync` continues to the next branch, matching decisions/0018's mirror-only-surprise precedent rather than decisions/0023's setup-time hard-fail — a branch decisions/0017 merely discovered, never named in `config.branches`, shouldn't block every other branch's sync. `config.branches`' own hard-fail on a missing trailer is unchanged.
* [0025-authenticated-mapping-markers](0025-authenticated-mapping-markers.md) - Human-readable mapping trailers remain for inspection, but only a canonical final HMAC-SHA256 state block keyed by `GITPRISM_STATE_KEY` can advance resume or loop-prevention state; the MAC binds direction, branch, counterpart, commit shape, identities, and message body.
* [0026-protected-versioned-policy](0026-protected-versioned-policy.md) - Versioned `.gitprism.toml` and `.gitprismignore` remain reviewable, but mutating commands require an external SHA-256 pin over their exact bytes; sync uses one verified exclude list for the entire run.
* [0027-source-to-dest-resolution-state](0027-source-to-dest-resolution-state.md) - Source-to-dest conflicts use an authenticated Git operation ref and filtered synthetic patch in an isolated linked worktree; continuation rejects stale policy, source, patch, and excluded-path edits.
* [0028-operation-lock-and-local-advance-cas](0028-operation-lock-and-local-advance-cas.md) - Mutating commands serialize per Git common directory, and dest-to-source local advancement uses a clean-checkout preflight plus compare-and-swap ref update.
* [0029-operator-resolution-identity-and-process-boundary](0029-operator-resolution-identity-and-process-boundary.md) - Conflict handling remains fail-fast and operator-driven; temporary dest-to-source commits use the configured identity, gitprism credential/state values are scrubbed from Git children, and Git configuration/hooks remain an explicit trust boundary.
* [0030-byte-safe-git-data](0030-byte-safe-git-data.md) - Preserve Git path bytes for comparisons and diagnostics, escape terminal output deterministically, and reject unsupported non-UTF-8 commit messages, tree names, and refs before mutation.
* [0031-centralized-git-process-runner](0031-centralized-git-process-runner.md) - Centralize Git execution with null stdin, disabled terminal prompting, concurrent bounded capture, and a bounded operator-configured deadline.
* [0032-bounded-repository-controlled-data](0032-bounded-repository-controlled-data.md) - Bound control-file reads, commit messages, tree traversal, branch collections, conflict reporting, pending history, and marker scans with static fail-closed limits.
* [0033-authenticated-resolution-worktree-and-safe-file-recovery](0033-authenticated-resolution-worktree-and-safe-file-recovery.md) - Sign and validate the exact source-to-dest resolution worktree, and use opened-handle/create-new file operations for race-safe reads and setup recovery.
* [0034-control-files-stay-byte-exact-through-checkout](0034-control-files-stay-byte-exact-through-checkout.md) - `.gitprism.toml`/`.gitprismignore` are re-materialized straight from their blob bytes after every checkout that might place them, bypassing `core.autocrlf`/`.gitattributes` text filtering that could otherwise invalidate decision 0026's pinned digest for reasons unrelated to any real content change; every other file keeps its ordinary checkout attributes.
* [0035-pending-history-is-first-parent](0035-pending-history-is-first-parent.md) - `pending_commits`, shared by both sync directions, gains `Revwalk::simplify_first_parent()` so a merge is carried as one net change against its first parent instead of replaying a side branch's own commits against a base tree the apply step's `parent(0)`-based merge base was never built for; amends decisions/0019's stated limitation that no change was made to `pending_commits` or the `build_pending_*_tip` walks.
* [0036-branch-additive-exclusions](0036-branch-additive-exclusions.md) - Superseded by decisions/0037. Amends decisions/0026's "does not load branch-tip versions of the ignore file" clause: effective source→dest exclusion becomes the trusted, digest-pinned policy OR the union of every replayed commit's own `.gitprismignore`, evaluated as two independent matchers so a branch can only add exclusions, never negate the trusted ones — closing a disclosure path where a branch's own "do not export this" instruction was silently discarded.
* [0037-branch-policy-mismatch-fails-closed](0037-branch-policy-mismatch-fails-closed.md) - Supersedes decisions/0036's additive-exclusion union with a fail-closed halt: a source→dest branch replaying a commit whose control file is present and differs from the digest-pinned working-tree policy stops that branch (Outcome::Error, non-zero run exit) instead of merging the branch's own exclusions into policy; absence isn't a mismatch, other branches keep syncing, and decisions/0026's single verified ExcludeList is otherwise unchanged. Amended 2026-08-27: `gitprism resolve --direction source-to-dest` runs the identical pre-pass before building or pushing anything, and again against the specific commit being resolved at `--continue` time — it was recomputing the same pending list without the check, reopening the disclosure path this decision closes (review finding F-03).
* [0038-branch-authority-determines-whether-history-may-be-rewritten](0038-branch-authority-determines-whether-history-may-be-rewritten.md) - Force semantics depend on branch authority, not push direction: round-tripped branches (`config.branches`) stay fast-forward-only in both directions with divergence an operator boundary; mirror-only branches may be force-updated on source→dest to match a deliberately rewritten source branch, via an explicit `PushMode` every call site must declare. Two of its conclusions have since been overturned in the file itself: the retry-exhaustion trigger (superseded by decisions/0039, which positively identifies the rewrite instead) and the blanket "no `--force-with-lease` anywhere" (revised by decisions/0040, which adopts an explicit lease as compare-and-swap around an already-authorized mirror-only force; round-tripped branches keep zero lease exposure). Formalizes requirements/0001 step 3 as amended in `cdac783`.
* [0039-mirror-only-source-rewrites-rebuild-the-projection](0039-mirror-only-source-rewrites-rebuild-the-projection.md) - Extends decisions/0038: a rewritten mirror-only branch is positively identified (mirror-only, dest ref exists, a prior marker exists, source no longer descends from the prior boundary) rather than reached by exhausting retries, and rebuilds its dest projection from the same graft-derived `(boundary, dest_tip)` the `!dest_ref_exists` path already reads off source's own history, then force-pushes it. Narrows 0038's `resolve.rs` guidance: `resolve` never performs this detection, so every `resolve.rs` push stays fast-forward-only regardless of branch authority. Addendum: a missing boundary object (a fresh CI clone never had the pre-rewrite tip) is confirmed as the rewrite itself on a non-shallow clone (`Repository::is_shallow`), rather than refused as ambiguous; a shallow clone keeps refusing.
* [0040-mirror-only-force-is-a-compare-and-swap-lease](0040-mirror-only-force-is-a-compare-and-swap-lease.md) - Fixes a lost-update race: `PushMode::ForceMirrorOnly`'s unconditional `+`-prefixed refspec could silently overwrite a concurrent dest advance between fetch and push, with no rejection for decisions/0009's retry loop to catch. Replaces it with an explicit `--force-with-lease=refs/heads/<branch>:<fetched-dest-oid>` compare-and-swap, verified to route a stale lease into the existing retry mechanism with no new plumbing; `PushMode::ForceMirrorOnly` gains a required `expected_dest: Oid` field. Revises decisions/0038's blanket "no lease mechanism anywhere" for mirror-only force only — round-tripped branches keep zero lease exposure.
* [0041-dest-to-source-fetches-its-own-configured-branch-when-absent-locally](0041-dest-to-source-fetches-its-own-configured-branch-when-absent-locally.md) - `sync_pair_from_dest_with_key`'s first attempt no longer assumes a `config.branches` entry is already a local branch (false under GitLab CI's default single-ref checkout): on `find_branch` NotFound it fetches `branch` from source's own remote and creates the local branch from the fetched tip, the same fetch already used one branch-state later on a push-race retry — no CI reconfiguration needed, and `preflight_local_source_branch`/`advance_local_source_branch` need no special-casing since a real local ref now exists.
* [0042-gitprism-toml-drops-out-of-the-per-commit-policy-check](0042-gitprism-toml-drops-out-of-the-per-commit-policy-check.md) - Amends decisions/0037: only `.gitprismignore` is compared per pending commit going forward — `.gitprism.toml` has no content-disclosure vector (self-excluded, doesn't gate per-commit filtering) and keeps only decisions/0026's single global verification, removing the forced-history-rewrite friction a real deployment hit while iterating on the config before its first successful sync.
* [0043-mirror-only-branches-graft-onto-their-nearest-mirrored-ancestor](0043-mirror-only-branches-graft-onto-their-nearest-mirrored-ancestor.md) - Superseded by decisions/0046. A discovered branch's dest anchor search now also looks for the most specific already-mirrored sibling branch (via `merge_base` + `graph_descendant_of` specificity comparison over every branch with an existing dest ref, round-tripped or mirror-only), falling back to `scan_for_dest_marker`'s existing Setup/DestToSource baseline when none is more specific — fixing Azure/GitLab PR diffs showing already-merged commits for a branch forked from another mirror-only branch (e.g. task branches off a mirror-only feature branch). Ambiguous ties (incomparable most-specific candidates) hard-fail, naming both. Amended 2026-08-27: a missing boundary object is no longer confirmed as a rewrite by `Repository::is_shallow()` — that check doesn't distinguish a genuine rewrite from an ordinary stale (behind, non-shallow) clone, which was force-pushing dest backwards (review finding F-01). Amended again 2026-08-27: a `DestToSource` marker commit, once an ancestor of a branch's tip and self-verified against its own recorded branch (never the asking branch — `marker::verify` unchanged), now counts for that branch's loop prevention and is usable by step 5 as an anchor resolving to the dest commit it names — a branch forked after a dest-native commit was reflected into a sibling was re-projecting that commit as a duplicate (review finding F-04).
* [0044-a-branchs-dest-ref-always-carries-its-own-marker](0044-a-branchs-dest-ref-always-carries-its-own-marker.md) - A branch's dest ref is never created or rebuilt at a commit its own `dest_tip_accounted_for` check wouldn't recognize next run: when nothing was built for a brand-new or rebuilt branch, the fallback anchor (a sibling's dest tip per decisions/0043, or a rewrite's rebuild base) is checked against that exact branch name first, and a content-empty, branch-scoped marker commit (via the existing `build_dest_commit`) is built on top of it if the anchor isn't already self-accounted-for — fixing a permanent-refusal bug (review finding F-02) where a sibling-anchored branch with no commits of its own bailed on every later resync.
* [0045-discovered-branch-refusals-are-per-branch-halts](0045-discovered-branch-refusals-are-per-branch-halts.md) - The two remaining fatal refusal sites decisions/0024/0037/0043's per-branch-halt rollout missed — `dest_resume_point_for_branch`'s "isn't at a point this clone can safely build on" bail and `graft_point`'s "no shared history" merge-base failure — become the same per-branch `Outcome::Error` + `Ok(true)` pattern for a branch outside `config.branches`, leaving round-tripped branches' identical refusal fatal and unchanged (review finding F-05); `graft_point` changes from erroring on no merge-base to `Result<Option<Oid>>`, and the discovered-branch message drops the "dest→source hasn't reflected its content yet" clause that can never apply to a branch dest→source never touches.
* [0046-dest-anchors-come-from-exact-authenticated-mappings](0046-dest-anchors-come-from-exact-authenticated-mappings.md) - Supersedes decisions/0043's global sibling merge-base inference: each CI run reconstructs a bounded in-memory source→dest index from existing authenticated commit markers, anchors a new or rewritten branch at its nearest exactly mapped first-parent ancestor, and processes branches by increasing distance from known mapping state so parents created in the same run precede children. Durable state remains in Git; empty branch-marker aliases and comparable mappings normalize automatically, while only incomparable canonical mappings for the same source OID halt.
* [0047-an-undecodable-dest-ref-makes-the-listing-incomplete](0047-an-undecodable-dest-ref-makes-the-listing-incomplete.md) - `git::remote_branch_names` stops decoding `git ls-remote --heads` output with `String::from_utf8_lossy`, which fabricated a U+FFFD branch name that passed validation, was recorded as an existing dest ref, then failed to fetch and aborted every branch's sync (review finding M-02). An advertised ref whose name isn't valid UTF-8 is now dropped and marks the listing incomplete — decisions/0046 Addendum 2, Finding F's existing signal — so reconstruction degrades to a per-branch refusal; `RemoteBranchListing.truncated: bool` becomes `incomplete: Option<ListingIncomplete>` so the refusal names the actual cause. A well-formed name that merely fails `validate_branch_name` keeps decisions/0024's silent skip. Amended 2026-08-31 (review finding M-03): the listing carries every incompleteness cause rather than the first one seen, and only the branch-limit horizon blocks a "dest has no branch by this name" claim, so an unrelated undecodable ref no longer disables decisions/0046 Addendum 2, Finding G's deleted-ref recovery or the negative-existence seeding.
